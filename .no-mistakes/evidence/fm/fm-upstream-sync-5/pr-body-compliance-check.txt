  B is the trap this change must not walk into. The check strips to the
  FIRST "<!-- no-mistakes-pipeline-attestation:v1 " it finds, so a placeholder
  shown as documentation is parsed as the attestation. Its {"steps":[...]}
  is not valid JSON, so a fully compliant PR is failed with a message that
  reads like an out-of-date tool - even though the real attestation is right
  there further down the body. Case A is the same body without the
  placeholder and it passes.
